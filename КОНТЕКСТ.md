## 1. Что это

Тренажёр казахской грамматики для русскоязычных школьников 12–17 лет. Веб-приложение, работает офлайн, ставится на телефон.

Проект готовится к защите на олимпиаде научных проектов (Дарын / Зерде / НИШ). Автор-докладчик — школьник; ему нужно не только показать продукт, но и объяснить, как он устроен.

## 3. Что было не так в версии 5.0

Всё перечисленное — проверенные факты, а не предположения.

### Проверка ответов не работала для казахского

166 из 187 правильных ответов содержат буквы `ә ғ қ ң ө ұ ү һ і`. На русской раскладке их физически негде взять, а проверка была строгим сравнением строк. Школьник, ответивший грамматически верно, получал «неправильно».

### Пять типов заданий существовали только на бумаге

Ни у одного из 187 шагов в `lessons.json` не было поля `taskType`. Работал ровно один тип — ввод текста. Остальные четыре были мёртвым кодом.

### Задание на сопоставление уронило бы приложение

В `TaskInput.tsx` `useState` вызывался внутри условной функции рендера. Нарушение правил хуков React: при переключении типа задания порядок хуков ломается и экран падает.

### Шрифты не содержали казахских букв

Проверено разбором cmap скачанных файлов:

- **Manrope** (основной) — нет `ә ғ қ ң ұ`
- **Playfair Display** (заголовки) — нет 7 из 9

Эти буквы молча подменялись системным шрифтом — в приложении для изучения казахского ключевые символы рендерились чужой гарнитурой.

### Шрифты грузились с Google CDN

Приложение заявлено как офлайн-PWA, но шрифт приезжал из сети. Без интернета — подмена.

### Изображения персонажей весили 11 МБ

Семь PNG по 1024×1024 (~1,6 МБ каждый) при отображении в 44–96 px. Вокруг фигур запечена полупрозрачная серая дымка — персонаж выглядел вставленным в грязный прямоугольник.

### Интервального повторения не было

Экран «Повторение» существовал, алгоритма не было — он просто прогонял пройденное подряд.

### Переключатель языка почти не работал

Проверка ответа всегда шла по `step.answerKz`, задание всегда показывалось по-казахски.

### Дизайн противоречил собственной документации

`STATUS-v5.md` перечисляет glassmorphism и градиенты как «AI slop, чего избегать». `PROJECT_CONTEXT.md` хвалит их как достижение. В коде были и glassmorphism, и mesh-градиенты, и частицы, и 3D-наклон карточек.

### Содержание уроков было двусмысленным

Казахская ветка учит казахской грамматике, русская — русской, но подписаны они как «перевод». Согласовано: продукт учит **казахскому для русскоязычных**, русский — только подсказка.

## 4. Что сделано

### 4.1 Механика

**Движок проверки ответов** — `src/utils/answer.ts`

Многослойная проверка вместо сравнения строк:

1. Точное совпадение
2. Совпадение после свёртки казахских букв к русским (снимает проблему раскладки) → ответ засчитывается, показывается правильное написание
3. Расстояние Левенштейна для опечаток, бюджет зависит от длины ответа
4. Варианты через `/`, пояснения в скобках

Вердикты: `correct` / `correct_kz` / `almost` / `wrong`. Короткие ответы опечатки не прощают — иначе «тұр» и «тұт» слились бы.

**Экранная клавиатура казахских букв** — ряд `ә ғ қ ң ө ұ ү һ і` под каждым полем ввода.

**Интервальное повторение** — `src/utils/srs.ts`

Упрощённый SM-2. Каждый шаг урока — карточка. Интервалы 1 → 3 → дальше по коэффициенту лёгкости, потолок 180 дней. Ошибка возвращает карточку на сегодня. В очередь первыми идут те, что забывались чаще.

**Метрики и выгрузка** — `src/utils/metrics.ts`

Журнал ответов: тип задания, вердикт, время на ответ, подсказки. Выгрузка CSV с разделителем `;` и BOM — Excel на Windows открывает кириллицу без плясок. Личные данные не собираются, только метка участника.

### 4.2 Контент

**Генератор заданий** — `tools/enrich_lessons.py`

Детерминированно превращает `lessons.source.json` в `lessons.json`, раскладывая 187 шагов по семи типам:

| Тип | Сколько |
|---|---|
| `fill_blank` — пропуск в предложении | 52 |
| `choice` — выбор из 4 вариантов | 44 |
| `word_order` — сборка предложения | 29 |
| `open` — развёрнутый ответ с самопроверкой | 23 |
| `input` — свободный ввод | 15 |
| `matching` — сопоставление формы и перевода | 13 |
| `translate` — перевод на казахский | 11 |

**Дистракторы для выбора** строятся по правилам казахской морфологии: смена лица с сохранением сингармонизма (`ішемін / ішесің / ішеміз / ішесіз`), смена времени, другие формы того же глагола для деепричастий на `-ып/-іп`.

Кандидаты с невозможными стыками (`гласная+гласная`, `й+гласная`) отбраковываются — лучше простой дистрактор, чем выдуманная форма, на которой ученик запомнит неправильное.

**Правка контента только через `lessons.source.json`**, затем `npm run data`. Прямая правка `lessons.json` будет затёрта.

### 4.3 Дизайн

Убрано: glassmorphism, mesh-градиенты, частицы, 3D-наклон, градиентные кнопки со свечением, эмодзи вместо иконок, заглавные «надзаголовки» над каждым блоком.

**Шрифт** — Golos Text, вшит в бандл (4 сабсета, 96 КБ). Полное покрытие казахских букв проверено разбором cmap. Спроектирован под кириллические интерфейсы.

**Палитра** — OKLCH, светлая тема по умолчанию, полноценная тёмная, переключатель «как в системе / светлая / тёмная».

Контраст проверяется скриптом `tools/contrast.py` — 28 проверок WCAG AA, все проходят. **Палитру править только вместе с прогоном скрипта.**

**Типографика** — фиксированная шкала кегля (шаг ≈1,2), без текучего `clamp`: в интерфейсе задачи заголовок не должен съёживаться в узкой колонке.

**Движение** — 140–280 мс, экспоненциальный ease-out, без отскока. Полная поддержка `prefers-reduced-motion`.

**Правило, которое легко нарушить снова:** видимость содержимого не должна зависеть от анимации. `initial={{ opacity: 0 }}` на замороженной вкладке не доигрывает, и экран остаётся пустым. Анимируется только сдвиг.

**Изображения** — `tools/optimize_characters.py`: гасит дымку, обрезает по фигуре, уменьшает до 320 px, сохраняет WebP. **11,1 МБ → 165 КБ.** Исходные PNG лежат в `assets-source/characters/`.

### 4.4 Экраны

`/` приветствие · `/menu` главное · `/lessons` список · `/lesson/:id` урок · `/review` повторение · `/rules` правила · `/reference` справочник · `/stats` статистика и настройки

Роутер — `HashRouter`, не `BrowserRouter`: в APK приложение загружается не с обычного адреса, и history API там ломается на переходах.

### 4.5 Мобильное приложение

- **PWA** — работает сейчас, ставится из браузера на Android и iPhone
- **APK** — Capacitor 8, нативный проект в `android/`, сборка в GitHub Actions (локально Android SDK не нужен — на этой машине его и нет)

### 4.6 Тесты

31 тест, без внешних зависимостей — собираются esbuild-ом, бегут в node:

- `tools/tests/answer.test.ts` — 16 тестов движка проверки
- `tools/tests/srs.test.ts` — 15 тестов повторения и метрик

Запуск: `npm test`. Гоняются и в облачной сборке перед APK.

### 4.7 Презентация

`презентация/` — 18 слайдов под регламент научного проекта, PPTX + PDF, движок `deckkit.py`, заметки докладчика внутри файла. Подробности — `презентация/ЧИТАТЬ-ПЕРВЫМ.md`.

**Незаполненное:** ФИО школьника, класс, школа, город, научный руководитель — прочерки в шапке `build.py`.

## 8. Чего не повторять

- **Не править `lessons.json` руками** — правки затрёт `npm run data`.
- **Не менять палитру без `tools/contrast.py`** — контраст рассчитан, а не подобран на глаз.
- **Не возвращать `initial={{ opacity: 0 }}`** на появление экранов — содержимое пропадает, если анимация не доиграла.
- **Не ставить `mode="wait"` у `AnimatePresence`** там, где от этого зависит показ следующего шага.
- **Не подключать шрифты с Google CDN** — приложение обязано работать офлайн.
- **Не игнорировать `android/app/src/main/assets/` целиком** — git не хранит пустые каталоги, и облачная сборка падает. В каталоге лежит `.gitkeep`, он нужен.
- **Не заменять шрифт, не проверив покрытие казахских букв** — большинство популярных гарнитур их не содержит.

## 9. Текущий статус

**Готово и проверено:**

- Боевой сайт обновлён, публичный, отдаёт версию 6.0
- PWA ставится на телефон из браузера
- 31 тест зелёный, типы сходятся, сборка проходит
- Презентация собрана: PPTX + PDF, 18 слайдов
- Палитра проходит 28 проверок WCAG AA

**Не готово:**

- **APK.** Три облачные сборки упали подряд. Найдены и исправлены три причины, все — из-за того, что нативный проект изначально не хранился в репозитории:

  1. `npx cap add android` ведёт себя по-разному в зависимости от того, что установлено на машине. Убрано: нативный проект теперь в репозитории.
  2. Каталог `android/app/src/main/assets/` не существовал после клонирования — git не хранит пустые каталоги, а всё содержимое было в `.gitignore`. Добавлен `.gitkeep`.
  3. `cap sync` = `copy` + `update`, а шаг `update` при установленном на раннере Android SDK запускает собственную синхронизацию Gradle; флага отключения нет. Заменено на `cap copy`. Заодно оказалось, что модуль `capacitor-cordova-android-plugins`, на который ссылается `settings.gradle`, игнорировался вложенным файлом `android/.gitignore` — тем, что пишет сам Capacitor.

  Последнее исправление отправлено, сборка перезапущена — **результат на момент написания неизвестен**. Смотреть во вкладке Actions.

  **Как диагностировать дальше.** Логи сборки закрыты без токена GitHub, а `gh` CLI на машине не установлен — поэтому три попытки подряд были догадками, и две из трёх оказались неверными. Правильный порядок: сначала воспроизвести CI локально (клон в чистую папку → `npm ci` → `npm run build` → команда шага), и только потом менять workflow. Если понадобится читать логи — поставить `gh` или открыть лог вручную по ссылке из Actions.

- **Титульные данные презентации** — прочерки ждут ФИО, класса, школы, руководителя.

- **Апробация** — инструмент готов, данных нет.
