## 1. Что это

Тренажёр казахской грамматики для русскоязычных школьников 12–17 лет. Веб-приложение, работает офлайн, ставится на телефон.

Проект готовится к защите на олимпиаде научных проектов (Дарын / Зерде / НИШ). Автор-докладчик — школьник; ему нужно не только показать продукт, но и объяснить, как он устроен.

## 3. Что было не так в версии 5.0

Всё перечисленное — проверенные факты, а не предположения.

### Проверка ответов не работала для казахского

166 из 187 правильных ответов содержат буквы `ә ғ қ ң ө ұ ү һ і`. На русской раскладке их физически негде взять, а проверка была строгим сравнением строк. Школьник, ответивший грамматически верно, получал «неправильно».

### Пять типов заданий существовали только на бумаге

Ни у одного из 187 шагов в `lessons.json` не было поля `taskType`. Работал ровно один тип — ввод текста. Остальные четыре были мёртвым кодом.

### Задание на сопоставление уронило бы приложение

В `TaskInput.tsx` `useState` вызывался внутри условной функции рендера. Нарушение правил хуков React: при переключении типа задания порядок хуков ломается и экран падает.

### Шрифты не содержали казахских букв

Проверено разбором cmap скачанных файлов:

- **Manrope** (основной) — нет `ә ғ қ ң ұ`
- **Playfair Display** (заголовки) — нет 7 из 9

Эти буквы молча подменялись системным шрифтом — в приложении для изучения казахского ключевые символы рендерились чужой гарнитурой.

### Шрифты грузились с Google CDN

Приложение заявлено как офлайн-PWA, но шрифт приезжал из сети. Без интернета — подмена.

### Изображения персонажей весили 11 МБ

Семь PNG по 1024×1024 (~1,6 МБ каждый) при отображении в 44–96 px. Вокруг фигур запечена полупрозрачная серая дымка — персонаж выглядел вставленным в грязный прямоугольник.

### Интервального повторения не было

Экран «Повторение» существовал, алгоритма не было — он просто прогонял пройденное подряд.

### Переключатель языка почти не работал

Проверка ответа всегда шла по `step.answerKz`, задание всегда показывалось по-казахски.

### Дизайн противоречил собственной документации

`STATUS-v5.md` перечисляет glassmorphism и градиенты как «AI slop, чего избегать». `PROJECT_CONTEXT.md` хвалит их как достижение. В коде были и glassmorphism, и mesh-градиенты, и частицы, и 3D-наклон карточек.

### Содержание уроков было двусмысленным

Казахская ветка учит казахской грамматике, русская — русской, но подписаны они как «перевод». Согласовано: продукт учит **казахскому для русскоязычных**, русский — только подсказка.

## 4. Что сделано

### 4.1 Механика

**Движок проверки ответов** — `src/utils/answer.ts`

Многослойная проверка вместо сравнения строк:

1. Точное совпадение
2. Совпадение после свёртки казахских букв к русским (снимает проблему раскладки) → ответ засчитывается, показывается правильное написание
3. Расстояние Левенштейна для опечаток, бюджет зависит от длины ответа
4. Варианты через `/`, пояснения в скобках

Вердикты: `correct` / `correct_kz` / `almost` / `wrong`. Короткие ответы опечатки не прощают — иначе «тұр» и «тұт» слились бы.

**Экранная клавиатура казахских букв** — ряд `ә ғ қ ң ө ұ ү һ і` под каждым полем ввода.

**Интервальное повторение** — `src/utils/srs.ts`

Упрощённый SM-2. Каждый шаг урока — карточка. Интервалы 1 → 3 → дальше по коэффициенту лёгкости, потолок 180 дней. Ошибка возвращает карточку на сегодня. В очередь первыми идут те, что забывались чаще.

**Метрики и выгрузка** — `src/utils/metrics.ts`

Журнал ответов: тип задания, вердикт, время на ответ, подсказки. Выгрузка CSV с разделителем `;` и BOM — Excel на Windows открывает кириллицу без плясок. Личные данные не собираются, только метка участника.

### 4.2 Контент

**Генератор заданий** — `tools/enrich_lessons.py`

Сборка контента идёт в два шага (`npm run data`):

1. `tools/content/build.py` объединяет исходные 18 уроков и базовый курс из
   `tools/content/beginner.py`, проставляет уровни и выгружает новое на проверку
2. `tools/enrich_lessons.py` раскладывает 225 шагов по семи типам и собирает словарь

| Тип | Сколько |
|---|---|
| `fill_blank` — пропуск в предложении | 63 |
| `choice` — выбор из 4 вариантов | 56 |
| `open` — развёрнутый ответ с самопроверкой | 23 |
| `input` — свободный ввод | 22 |
| `word_order` — сборка предложения | 22 |
| `matching` — сопоставление формы и перевода | 21 |
| `translate` — перевод на казахский | 18 |

На первом уровне сборка предложений не даётся: ученик ещё не знает порядка
слов, поэтому вместо неё ставится пропуск.

**Дистракторы для выбора** строятся по правилам казахской морфологии: смена лица с сохранением сингармонизма (`ішемін / ішесің / ішеміз / ішесіз`), смена времени, другие формы того же глагола для деепричастий на `-ып/-іп`.

Кандидаты с невозможными стыками (`гласная+гласная`, `й+гласная`) отбраковываются — лучше простой дистрактор, чем выдуманная форма, на которой ученик запомнит неправильное.

**Правка контента.** Исходные уроки — `src/data/lessons.source.json`, базовый
курс — `tools/content/beginner.py`. После правки обязательно `npm run data`.
Файлы `lessons.json`, `lessons.merged.json` и `vocabulary.json` генерируются —
править их напрямую бесполезно.

Для служебных слов дистракторы задаются вручную в `DISTRACTORS` внутри
`beginner.py`: у них нет окончаний, и правило подставляет случайные слова урока.

### 4.3 Дизайн

Убрано: glassmorphism, mesh-градиенты, частицы, 3D-наклон, градиентные кнопки со свечением, эмодзи вместо иконок, заглавные «надзаголовки» над каждым блоком.

**Шрифт** — Golos Text, вшит в бандл (4 сабсета, 96 КБ). Полное покрытие казахских букв проверено разбором cmap. Спроектирован под кириллические интерфейсы.

**Палитра** — OKLCH, светлая тема по умолчанию, полноценная тёмная, переключатель «как в системе / светлая / тёмная».

Контраст проверяется скриптом `tools/contrast.py` — 28 проверок WCAG AA, все проходят. **Палитру править только вместе с прогоном скрипта.**

**Типографика** — фиксированная шкала кегля (шаг ≈1,2), без текучего `clamp`: в интерфейсе задачи заголовок не должен съёживаться в узкой колонке.

**Движение** — 140–280 мс, экспоненциальный ease-out, без отскока. Полная поддержка `prefers-reduced-motion`.

**Правило, которое легко нарушить снова:** видимость содержимого не должна зависеть от анимации. `initial={{ opacity: 0 }}` на замороженной вкладке не доигрывает, и экран остаётся пустым. Анимируется только сдвиг.

**Изображения** — `tools/optimize_characters.py`: гасит дымку, обрезает по фигуре, уменьшает до 320 px, сохраняет WebP. **11,1 МБ → 165 КБ.** Исходные PNG лежат в `assets-source/characters/`.

### 4.4 Экраны

С нижней панелью: `/learn` путь обучения · `/practice` практика ·
`/dictionary` словарь · `/reference` справочник (+ `/rules`, `/topics`,
`/tables`) · `/stats` профиль

На весь экран, без панели: `/` приветствие · `/lesson/:id` урок ·
`/review` повторение · `/cards` карточки · `/sprint` спринт

Роутер — `HashRouter`, не `BrowserRouter`: в APK приложение загружается не с обычного адреса, и history API там ломается на переходах.

### 4.5 Мобильное приложение

- **PWA** — работает сейчас, ставится из браузера на Android и iPhone
- **APK** — Capacitor 8, нативный проект в `android/`, сборка в GitHub Actions (локально Android SDK не нужен — на этой машине его и нет)

### 4.6 Тесты

70 тестов, без внешних зависимостей — собираются esbuild-ом, бегут в node:

- `tools/tests/answer.test.ts` — 27, движок проверки ответов и задания с пропуском
- `tools/tests/srs.test.ts` — 15, интервальное повторение и метрики
- `tools/tests/morphology.test.ts` — 21, склонение и спряжение
- `tools/tests/helpers.test.ts` — 7, говорящий в реплике и склонение числительных

Запуск: `npm test`. Гоняются и в облачной сборке перед APK.

### 4.7 Презентация

`презентация/` — 18 слайдов под регламент научного проекта, PPTX + PDF, движок `deckkit.py`, заметки докладчика внутри файла. Подробности — `презентация/ЧИТАТЬ-ПЕРВЫМ.md`.

**Незаполненное:** ФИО школьника, класс, школа, город, научный руководитель — прочерки в шапке `build.py`.

## 4а. Что изменилось в версии 7

### Выбор языка убран

Приложение с самого начала сделано для тех, кто говорит по-русски и учит
казахский, — выбирать было нечего, а первый экран начинался с непонятного
вопроса. Теперь интерфейс русский, казахский живёт в содержании уроков.
Вместо выбора языка на первом экране — выбор уровня, который действительно
меняет то, с чего начнётся обучение.

### Три уровня вместо общего списка

| Уровень | Класс | Уроков | О чём |
|---|---|---|---|
| Начало | 5–7 | 12 | Первые слова, счёт, семья, школа, база грамматики |
| Уверенный | 7–9 | 7 | Септіктер и времена глагола |
| Свободный | 9–11 | 7 | Наклонения, залоги, сложная речь |

Уровень — ориентир, а не ограничение: переключается в одно касание, уроки
жёстко не запираются.

### Базовый курс для 5–7 классов

Курс начинался сразу с грамматики уровня 8–11 класса — пятикласснику не за
что было зацепиться. Добавлены восемь тематических уроков: знакомство, счёт,
семья, школа, цвета, еда, распорядок дня, погода. Лексика идёт впереди
грамматики, грамматика вводится небольшими порциями.

**Эти уроки писал ассистент, а не носитель языка.** Они помечены
`needsReview` и целиком выгружены в `НА-ПРОВЕРКУ-УЧИТЕЛЮ.md` — до проверки
живым учителем считать их готовыми нельзя.

### Пять новых разделов

- **Словарь** — 173 слова, собранных из самих уроков, поиск работает с
  русской раскладки, знакомые слова помечены
- **Карточки** — быстрая лексика по тому же алгоритму повторения
- **Спринт** — 60 секунд на скорость, ошибка отнимает три секунды, рекорд
  хранится на устройстве
- **Таблицы окончаний** — подставь своё слово, увидишь все формы с
  подсвеченным окончанием и объяснением, почему выбрано именно оно
- **Профиль** — статистика, настройки, выгрузка CSV

Навигация переехала на нижнюю панель: раньше до словаря или статистики нужно
было возвращаться через несколько экранов.

### Что взято из Duolingo

- **Карта-путь** вместо списка уроков: видно пройденное и следующий шаг
- **Цель на день** и календарь недели
- **Разбор ошибок** в конце урока с повторным проходом (без начисления XP —
  он нужен, чтобы разобраться, а не набрать очки)
- **Мгновенная реакция** на выбор варианта, без кнопки «Проверить»

### Морфология

Отдельный модуль `src/utils/morphology.ts` с правилами сингармонизма,
озвончения и выбора окончания по последнему звуку. Покрыт 21 тестом на
учебниковых формах. Именно на нём работают таблицы окончаний.

Тонкие места, которые уже ловились тестами:

- «кітап» + «ым» даёт **«кітабым»**: конечные қ, к, п озвончаются перед
  гласным окончанием
- «оқы» + личное окончание даёт **«оқимын»**, и ряд гармонии берётся от
  исходной основы — по букве «и» его восстановить нельзя
- множественное число: после р, й, у ставится -лар/-лер, а после л, м, н, ң —
  -дар/-дер; общего правила «все сонорные одинаково» нет

### Анимации

Движение добавлено туда, где оно несёт смысл: верный ответ подпрыгивает,
неверный вздрагивает, счётчик XP пробегает значения, галочка на пройденном
узле прорисовывается, варианты появляются по очереди, персонаж меняет позу
по результату. Всё отключается по `prefers-reduced-motion`.

Библиотека анимаций убрана: она осталась ради простых сдвигов, которые
переехали в CSS.

### Озвучка — система готова, аудио нет

Проверено: встроенная в браузер озвучка для казахского не работает. На типовой
машине 157 голосов и **ни одного казахского**. Поэтому браузерный синтез не
используется вовсе — иначе казахский текст читается чужим языком.

Что сделано:

- отобраны **372 фразы** (15 512 символов): слова, ответы, реплики диалогов;
  грамматические объяснения намеренно не озвучиваются — на слух они не
  воспринимаются
- `tools/tts/synthesize.py` — синтез через Azure (`kk-KZ-AigulNeural`,
  `kk-KZ-DauletNeural`), ключ берётся из переменных окружения
- `tools/tts/фразы-для-записи.md` — список для записи живым голосом
- кнопка «послушать» показывается только там, где запись есть

**Для защиты запись живого носителя сильнее платного синтеза.**

### Размер сборки

935 → 761 КБ (gzip 241 → 190 КБ). Убрана библиотека анимаций, манифест
озвучки разделён: в браузер уходит только пара «код-текст».

## 6. Команды

```bash
npm run dev       # разработка, порт 5173
npm test          # 31 тест
npm run data      # пересобрать контент: уровни, задания, словарь, список на проверку
npm run build     # продакшн-сборка
```

```bash
python3 tools/contrast.py          # проверка палитры, обязательно после правки цветов
python3 tools/contrast.py --hex    # то же плюс hex-значения
```

```bash
python3 tools/tts/build_manifest.py   # пересобрать список фраз для озвучки
python3 tools/tts/synthesize.py       # синтез через Azure (нужен ключ в окружении)
```

```bash
git push origin main               # деплой прода + сборка APK
vercel deploy --yes                # preview, прод не трогает
```

Пересборка презентации:

```bash
cd презентация && ./venv/bin/python build.py
```

## 7. Согласованные решения

| Вопрос | Решение |
|---|---|
| Чему учит | Казахскому для русскоязычных; русский — подсказка |
| Мобильное приложение | APK через Capacitor + доработанный PWA |
| Где собирать APK | GitHub Actions, локально SDK не ставим |

## 8. Чего не повторять

- **Не править `lessons.json` руками** — правки затрёт `npm run data`.
- **Не менять палитру без `tools/contrast.py`** — контраст рассчитан, а не подобран на глаз.
- **Не возвращать `initial={{ opacity: 0 }}`** на появление экранов — содержимое пропадает, если анимация не доиграла.
- **Не ставить `mode="wait"` у `AnimatePresence`** там, где от этого зависит показ следующего шага.
- **Не подключать шрифты с Google CDN** — приложение обязано работать офлайн.
- **Не игнорировать `android/app/src/main/assets/` целиком** — git не хранит пустые каталоги, и облачная сборка падает. В каталоге лежит `.gitkeep`, он нужен.
- **Не заменять шрифт, не проверив покрытие казахских букв** — большинство популярных гарнитур их не содержит.
- **Не расширять допуск на опечатки** — в казахском два символа это целое окончание, то есть другое лицо. Прощается только потерянная или лишняя буква, но не подменённая.
- **Не отдавать страницу из кэша первой** — иначе обновления не доходят до вернувшихся, и никакая правка внутри приложения это не лечит.
- **Не подключать встроенную в браузер озвучку для казахского** — казахских голосов в системе нет, вместо казахского получится текст, прочитанный чужим языком.
- **Не менять морфологические правила без прогона `npm test`** — там 21 тест на учебниковых формах, и правила легко сломать в тонком месте.
- **Не считать базовый курс готовым до проверки учителем** — его писал ассистент, не носитель языка.

**Не готово:**

- **APK.** Четыре облачные сборки упали подряд.

  **Настоящая причина одна:** `@capacitor/cli@8.5.0` объявляет `engines: node >=22.0.0`, а в workflow стоял Node 20 — любой вызов `npx cap` на раннере падал. Локально Node 24, поэтому ошибка не воспроизводилась ни на чистом клоне, ни с `npm ci`. Исправлено, требование продублировано в `package.json`. Сборка перезапущена — **результат на момент написания неизвестен**, смотреть во вкладке Actions.

  **Три предыдущие правки были догадками и цель не поражали**, хотя две из них сами по себе полезны и оставлены:

  - нативный проект перенесён в репозиторий (так рекомендует Capacitor, сборка стала воспроизводимой);
  - `android/app/src/main/assets/` получил `.gitkeep`, модуль `capacitor-cordova-android-plugins` вынут из-под вложенного `android/.gitignore` — без этого `cap copy` + Gradle на чистом клоне действительно не собрались бы;
  - переход с `cap sync` на `cap copy` — обоснован (sync лишний раз дёргает Gradle), но падение вызывал не он.

  **Урок на будущее.** Логи сборки закрыты без токена GitHub, а `gh` CLI не установлен — из-за этого диагностика шла вслепую. Правильный порядок при падении CI: сначала сверить версии окружения (`node --version` против `engines` у зависимостей) и воспроизвести шаг локально на чистом клоне, и только потом менять структуру проекта. Проверка `engines` заняла одну команду и сняла бы вопрос сразу.
