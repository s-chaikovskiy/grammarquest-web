# Презентация к защите — что где лежит

**Десять слайдов**, построенных по четырём вопросам: что создано, для чего,
как и что здесь особенного. «Для чего» стоит перед «как» намеренно: жюри
нужно понять задачу раньше, чем способ её решения.

Колода собирается на двух языках из одной вёрстки. Тексты лежат отдельно,
поэтому казахская версия — это перевод строк, а не вторая презентация,
которую пришлось бы править параллельно.

Прежняя версия на восемнадцати слайдах лежит в `архив/`: она была построена
как разбор недостатков первой программы, а не как рассказ о сделанном.

| Файл | Для чего |
|---|---|
| **Тілашар-защита.pdf** | Русская версия. Это показываем жюри: откроется на любом компьютере одинаково, шрифты вшиты |
| **Тілашар-қорғау.pdf** | Казахская версия, то же содержание |
| `Тілашар-защита.pptx`, `Тілашар-қорғау.pptx` | Для правок. Перед открытием поставить шрифты из папки `шрифты/` |
| `все-слайды-защита.png`, `все-слайды-қорғау.png` | Контрольный лист: все 10 слайдов на одной картинке |
| `тексты.py` | **Все тексты обеих версий.** Правки текста делаются здесь |
| `build.py` | Вёрстка, одна на оба языка |
| `deckkit.py` | Движок: шрифты, сетка, компоненты |
| `контрольный-лист.py` | Собирает контрольную картинку из PDF |
| `сверка-цифр.py` | **Проверяет каждое число колоды по данным проекта.** Прогнать перед защитой |
| `выгрузка-на-проверку.py` | Собирает казахский текст на сверку учителю |
| `шрифты/` | Поставить перед открытием PPTX: выделить все файлы → двойной щелчок → «Установить» |
| `архив/` | Прежняя колода под старым названием. Не везти на защиту |

## Что заполнить перед защитой

Открыть `тексты.py`, в самом верху найти блок с данными автора и заменить прочерки:

```python
AUTHOR = "Малышко Макар Евгеньевич"
GRADE_RU = "6 «б» класс"
GRADE_KZ = "6 «б» сынып"
SCHOOL_RU = "школа №35"
SCHOOL_KZ = "№35 мектеп"
CITY = ""                     # город — вписать, если нужен на титуле
MENTOR_RU = ""                # научный руководитель, если есть
MENTOR_KZ = ""
```

Пустые поля не оставляют висящих разделителей — подпись собирается только
из заполненного.

Данные попадают на титул и на последний слайд обеих версий сразу.

## Пересборка после правки

```bash
./venv/bin/python build.py оба
```

```bash
soffice --headless --convert-to pdf "Тілашар-защита.pptx" "Тілашар-қорғау.pptx"
```

```bash
./venv/bin/python контрольный-лист.py "Тілашар-защита.pdf"
```

Сборка сама проверяет вёрстку. Если вывод заканчивается строкой «переполнений
в карточках нет» — всё сошлось, текст никуда не вылез.

Собрать только один язык: `build.py ru` или `build.py kz`.

## Проверка чисел

Каждое число в докладе должно пересчитываться из первоисточника — иначе оно
незаметно устаревает. Так уже случилось: после правок кода изменился вес
приложения, а слайд остался со старым числом.

```bash
cd презентация && ./venv/bin/python сверка-цифр.py
```

Скрипт печатает числа по данным проекта и показывает расхождения со слайдами.
Нужен свежий `npm run build` в корне — вес считается по сборке.

Утверждение слайда 07 про шрифты проверяется отдельно:

```bash
tools/.venv/bin/python tools/check_fonts.py --скачать
```

## Заметки докладчика

У каждого слайда в PPTX есть заметки: что говорить, на чём сделать паузу, что
проверить накануне. В PowerPoint они видны в режиме докладчика — на проекторе
их не будет. Открыть: вкладка «Вид» → «Заметки».

На последнем слайде в заметках лежат готовые ответы на пять вопросов, которые
жюри задаёт чаще всего. На слайде 09 — сценарий живого показа приложения
по шагам.

Заметки написаны по-русски в обеих версиях намеренно: это шпаргалка докладчика,
а не то, что видит зал.

## Про казахскую версию

**Казахский текст писал ассистент, а не носитель языка.** До проверки живым
учителем считать его готовым нельзя — ровно как и базовый курс уроков.
Что именно сверять — в `НА-ПРОВЕРКУ-КАЗАХСКИЙ-ТЕКСТ.md`.

## Про шрифты

**В PDF шрифты встроены** — он откроется одинаково на любом компьютере,
ставить ничего не нужно. Именно поэтому на защиту берут PDF.
**В PPTX шрифты не встроены** — перед открытием для правок поставьте все
восемь файлов из `шрифты/`, иначе редактор подставит другую гарнитуру
и вёрстка разъедется. Лицензии — `шрифты/ЛИЦЕНЗИИ.md`.

Гарнитура — Golos Text (лицензия OFL). Выбрана потому,
что полностью содержит казахские буквы **ә ғ қ ң ө ұ ү һ і**. У многих
популярных шрифтов их нет — именно на этом и построен слайд 07.

Имена шрифтов внутри файлов приведены к тем, которые запрашивает колода
(скрипт `переименовать-шрифты.py`). Без этого редактор подставляет другую
гарнитуру, строки перевёрстываются и текст наезжает друг на друга.

## Чего в презентации намеренно нет

- **Придуманных результатов апробации.** Слайд 17 — это план эксперимента,
  и в заметках прямо сказано, как честно ответить на вопрос «а результаты есть?».
  Как только эксперимент пройдёт, слайд заменяется реальными числами.
- **Утверждений о конкурентах без проверки.** Единственное такое утверждение —
  список курсов Duolingo — снабжено ссылкой и датой проверки. Перед защитой
  стоит перепроверить: список меняется.
- **Красивых круглых процентов.** Все числа получены из данных проекта
  скриптами, которые лежат в репозитории и запускаются заново. Сверка —
  `сверка-цифр.py` для содержания колоды и `tools/check_fonts.py` для
  утверждения про шрифты на слайде 07.
